# Citation Radar

**AEO site audit + AI citation tracking in one tool.**
Audit a site for AI-search readiness, get a prioritised fix list, and track whether
ChatGPT, Perplexity, Google AI Overviews and Claude actually cite your brand.

---

## Run it locally

```bash
git clone <this repo> && cd citationradar
npm install
cp .env.example .env.local        # then fill in DATABASE_URL and SESSION_SECRET
npm run db:migrate                # creates the schema
npm run db:seed                   # optional: demo workspace with 12 weeks of history
npm run dev
```

**→ http://localhost:3000**

Demo login after seeding:

| | |
|---|---|
| Email | `demo@citationradar.app` |
| Password | `demopassword1` |

The demo workspace is on the Agency plan so every feature is reachable. All seeded
citation rows are marked `mode = 'simulated'`.

### The only two required variables

```bash
DATABASE_URL="postgresql://…"                      # Neon, or any Postgres
SESSION_SECRET="$(openssl rand -base64 48)"        # 32+ characters
```

Everything else is optional. See **Degraded mode** below for exactly what changes
without each key.

## What it does

### 1. Free audit — no signup
Paste one URL on the landing page. Citation Radar fetches it the way an AI crawler does
(no JavaScript executed), reads `robots.txt`, `llms.txt` and the sitemap, and returns a
0–100 score with the top three fixes. This is the acquisition funnel; the rest of the fix
list is behind a free account. Rate-limited to 5 per IP per day.

### 2. Full site audit
A robots-aware, same-origin crawl up to the plan's page cap, scored across six weighted
pillars:

| Pillar | Weight | What it measures |
|---|---|---|
| AI crawler access | 25 | GPTBot, OAI-SearchBot, ClaudeBot, PerplexityBot, Google-Extended, CCBot |
| Content without JavaScript | 20 | Whether content exists in the raw HTML at all |
| Structured data | 20 | JSON-LD presence, validity, entity grounding, content typing |
| Answerability | 15 | One H1, clean outline, FAQ blocks, direct-answer openers |
| Answer surface | 10 | `llms.txt`, `llms-full.txt`, sitemap |
| Entity clarity | 10 | Brand consistency, `sameAs`, author, freshness |

**Score ceilings.** A weighted average alone understates a hard block: losing one check out
of thirty barely moves the total, so a site ChatGPT physically cannot read could still
grade an A. That would be a misleading headline number, so:

- a blocked **primary crawler** caps the score at **60**
- a site-wide `Disallow: /` caps it at **25**

The cap and its reason are stored with the audit and shown wherever the score is.

### 3. Prioritised fixes, not an issue dump
Every failed check becomes an issue with:
- **what it means** in plain English, safe to put in front of a client
- **why it matters** — the commercial consequence, not the spec reference
- **how to fix it** — the specific change, with a copy-paste snippet
- **impact ÷ effort** as the sort key, so the report ends in a work queue

Each issue carries a status (open / in progress / fixed / ignored), so the report *is* the
to-do list. With `ANTHROPIC_API_KEY` set, Claude writes the executive summary, a sequenced
action plan and per-issue tailoring on top of the same findings.

### 4. Citation tracking across four engines
Track the prompts your buyers actually type. Each check records whether your brand was
named, **where** in the answer relative to competitors, which URLs were cited, and your
**share of voice** — your mentions as a fraction of all tracked brands' mentions. "Cited:
yes" hides the fact that a competitor was named six times and you once.

### 5. White-label client reporting
Workspace branding (name, colour, footer, contact) applied to:
- **PDF exports** — audit and citation reports, generated by a dependency-free writer that
  runs in a serverless function, no headless browser
- **Client share links** — read-only, revocable, `noindex`, view-counted, no account needed

### 6. Scheduled runs via n8n
`POST /api/cron/weekly` with a bearer secret re-runs every active prompt for paid
workspaces. See [`docs/N8N.md`](docs/N8N.md).

## Degraded mode

Every external provider sits behind an interface with `isConfigured()`. **The app runs
fully with no third-party keys at all.**

| Capability | Without the key | With it |
|---|---|---|
| Crawling, scoring, fix list | **Always real** — needs no API key | — |
| ChatGPT citations | Deterministic simulation | `OPENAI_API_KEY` |
| Perplexity citations | Deterministic simulation | `PERPLEXITY_API_KEY` |
| Google AI Overviews | Deterministic simulation | `DATAFORSEO_LOGIN` + `DATAFORSEO_PASSWORD` |
| Claude citations | Deterministic simulation | `ANTHROPIC_API_KEY` |
| Fix recommendations | Built-in copy from the same findings | `ANTHROPIC_API_KEY` |
| Upgrades | Checkout returns 503 with the fix; limits still enforced | `STRIPE_SECRET_KEY` + price IDs |
| Scheduled runs | Endpoint returns 503 | `CRON_SECRET` |

Simulated results are seeded from a hash of the query, so the same prompt always gives the
same answer — charts move only when inputs move. **Every simulated row is stored with
`mode = 'simulated'` and labelled on every surface it reaches**, including the prompt
tracker, the dashboard, settings, and a banner on PDF exports. No simulated number can be
mistaken for a measured one.

### Running the smoke test

It exercises every flow over real HTTP: free audit, signup, a multi-page crawl, prompt
tracking, citation checks, PDF export, share links, the scheduled run, plan limits, tenancy
isolation and the SSRF guard.

```bash
npm run build && npm start &
node scripts/smoke.mjs                 # or: SMOKE_TEST_SITE=https://yoursite.com npm run smoke
```

By default it crawls `http://127.0.0.1:8081/`, which needs `CRAWL_ALLOW_PRIVATE_HOSTS=true`
(see below). Point `SMOKE_TEST_SITE` at any public URL to run it without that.

## Deploying to Vercel + Neon

1. Create a Neon project and copy the **pooled** connection string.
2. Import the repo into Vercel.
3. Set `DATABASE_URL`, `SESSION_SECRET` and `APP_URL` (plus any optional keys).
4. Run `npm run db:migrate` once against the Neon URL.
5. Point your Stripe webhook at `https://<app>/api/stripe/webhook` for
   `checkout.session.completed`, `customer.subscription.*` and `invoice.payment_failed`.

The data layer picks its driver from the connection string's host: Neon's HTTP driver for
`*.neon.tech` (no TCP pool to leak across serverless invocations), node-postgres otherwise.
The same code therefore runs against local Postgres in development and Neon in production.

## Security notes

- **Passwords**: scrypt (N=16384, r=8, p=1), 16-byte salt, NFKC-normalised, parameters
  stored in the hash so they can change without invalidating existing users.
- **Sessions**: 32 random bytes, stored only as SHA-256, `HttpOnly; SameSite=Lax; Secure`,
  revocable server-side.
- **Tenancy**: every query filters on the workspace taken from the session, never from the
  request body or URL.
- **SSRF**: the free audit takes a URL from anyone, so the crawler rejects private,
  loopback, link-local and CGNAT addresses, re-validates every redirect hop, and refuses
  non-HTTP(S) schemes.
  `CRAWL_ALLOW_PRIVATE_HOSTS=true` disables that guard — **only** set it on a trusted,
  non-public deployment that needs to audit staging sites.
- **Crawl politeness**: `robots.txt` honoured for our own agent, 1 request per 300ms per
  host, hard page cap, 12s timeout, 2 MB response ceiling.
- **Stripe**: webhook signatures verified before parsing; every event id recorded, so a
  replay is a no-op.
- **Cron**: constant-time bearer comparison.
